Guide

How this works

Fill in the fields, and this tool builds a link to the signup form and turns it into a QR code. Every value you enter is added to the link — when someone scans the code and signs up, those values are saved with their profile in Klaviyo, so you know where each signup came from.

Tip: with this guide open, clicking any field scrolls here to its explanation.

Store ID

A short identifier for the specific store or location this QR lives in — e.g. paris-marais. Saved with the signup as store_id, so you can tell which branch drove each subscriber.

City

Pre-fills the City field on the form so visitors don't have to type it. They can still change it before submitting.

Country

Pre-fills the Country field. Pick from the standard list — the value travels in the link as an ISO code (e.g. FR) and is shown to the visitor translated into their own language. Leave it empty to let the form auto-detect.

Channel

Where this code appears — e.g. qrcode, poster, receipt. Defaults to qrcode. Saved as channel.

QR / campaign code

A code for this specific QR or campaign — e.g. summer24. Use a unique value per printed code to track each one separately. Saved as qr_id.

UTM parameters

Standard marketing tags, stored with the signup and recognised by analytics tools:

utm_source — where (e.g. instagram) · utm_medium — type (e.g. qr) · utm_campaign — the campaign name · utm_term / utm_content — optional extras.

Source

A fixed label identifying which tool the signup came from — defaults to in-store-qr-api-form. Saved as source, so in Klaviyo you can separate signups from this QR form from those coming via the website, pop-ups, or manual import. Usually leave it as-is.

Starting language

Forces the form to open in a specific language — e.g. fr, es, ar. Leave blank to auto-detect from the visitor's browser and location.

Custom parameters

Add any other key / value pairs you want stored with the signup. The key becomes a custom property on the Klaviyo profile — useful for one-off tags this form doesn't cover.
